[^1]: Built for Docker Sandboxes, where a virtual machine is the boundary and the agent has sudo.

[^2]: A process that can write the program it runs can replace it, and the next start of the container runs the replacement.

[^3]: Building the same commit again gives the same image byte for byte, so a rebuild shows whether a published image really comes from its source. The image manifest of each platform keeps its digest, while the digest of a tag changes with every build because the provenance attestation records the build run.

[^4]: A password in the log reaches everything that collects logs, and a new one on every start signs every client out.

[^5]: PID 1 does not reap the processes its children leave behind, and the agent starts many.

[^6]: Tested with `--read-only` and a volume on the home directory, terminals and the file watcher load their libraries from the temporary directory.

[^7]: A tool installed outside the home volume is gone once the container is recreated.

[^8]: Measured for `linux/arm64` on 2026-11-17.

[^9]: Trivy 0.76.2 with `--scanners vuln` and its database of 2026-11-17, which cannot read the `opencode` binary of any image.

[^10]: Trivy does not read the VEX document Docker ships with the image, with it Docker Scout 1.24.0 reports 1 high, 9 medium, 28 low and 2 unspecified.

[^11]: All three are in the Go modules `golang.org/x/net` v0.61.0 and `golang.org/x/crypto` v0.58.0 of gh 2.104.0, not fixed yet in its newest release.
